The AWS services (Lambda, Bedrock, DynamoDB, Step Functions, API Gateway, etc.) become implementation details behind those capabilities.

One improvement I'd make
Rather than placing the Python packages at the repository root, I'd colocate all backend Python code under apps/backend to make imports, packaging, testing, and deployment cleaner.

A structure like this is more maintainable:

apps/
├── backend/
│   ├── app/
│   ├── agents/
│   ├── packages/
│   ├── tools/
│   ├── memory/
│   ├── tests/
│   └── requirements.txt
└── frontend/
This keeps the frontend and backend self-contained while preserving a clean monorepo. It will also simplify Lambda packaging and Terraform deployment later. Since we're only at Sprint 1, this is the ideal time to adopt that layout before any code depends on the directory structure.
